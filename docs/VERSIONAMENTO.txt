================================================================================
                       POLITICA DE VERSIONAMENTO E RELEASES
                               CREDITWATCH
================================================================================
Autor: Pablo Michelin

1. ESTRUTURA DE VERSAO (SemVer)
--------------------------------------------------------------------------------
Formato: MAJOR.MINOR.PATCH (ex: 0.11.4)
- MAJOR: Mudancas estruturais completas na arquitetura ou compatibilidade.
- MINOR: Adicao de novos provedores de IA ou novas telas/funcionalidades.
- PATCH: Correcoes de bugs, ajustes de parsers e melhorias de resiliencia.

2. NUMERO DE BUILD (CFBundleVersion)
--------------------------------------------------------------------------------
- Inteiro sequencial incremental (ex: 21 -> 22 -> 23 -> 24...).
- Todo commit com alteracao de codigo deve incrementar o build number.

3. CHECKLIST PARA PUBLICACAO DE RELEASE NO GITHUB
--------------------------------------------------------------------------------
Passo 1: Validar codigo e compilar em modo release:
         bash Scripts/build-app.sh

Passo 2: Incrementar versao no Info.plist, VERSION.txt e docs.

Passo 3: Fazer commit e push no git:
         git add .
         git commit -m "release: vX.Y.Z (Build N)"
         git push origin main

Passo 4: Gerar arquivo zip e criar Release no GitHub:
         zip -r -q "CreditWatch-vX.Y.Z-macOS.zip" "dist/CreditWatch.app"
         gh release create vX.Y.Z CreditWatch-vX.Y.Z-macOS.zip --title "CreditWatch vX.Y.Z" --notes "Notas da release"
         rm -f CreditWatch-vX.Y.Z-macOS.zip
